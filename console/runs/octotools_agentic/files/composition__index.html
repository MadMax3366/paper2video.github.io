PROBLEM

One prompt can't do it all

A single question can demand vision, calculation, and outside knowledge at once.

Plain prompting stalls on multi-step chains.

Existing tool frameworks are domain-locked, training-hungry, or single-step.

METHOD

Inside the framework — Figure 2

Fig. 2 — Tool cards feed a planner (action predictor + context verifier) and an executor (command generator + executor).

Tool cards — standardized metadata: inputs, outputs, limits, best practices. New tools plug in with no retraining.

Planner — one sub-goal and one tool per step; a verifier decides continue or stop.

Executor — turns each planned action into runnable Python and executes it.

TAKEAWAY

Smarter agents aren't bigger models —
they're better-organized ones.

Plan. Verify. Call the right tool. That's OctoTools.

Ever ask a model to solve a problem that needs a diagram, a calculation, and outside knowledge all at once?
That is where OctoTools starts: it treats complex reasoning as a workflow, not a single prompt.
Plain prompting often stalls when a task asks for vision, retrieval, and multi-step reasoning in one pass.
Existing tool systems can be tied to one domain, need training, or struggle to coordinate multiple steps reliably.
Figure 2 shows the setup: a training-free framework built around tool cards, a planner, and an executor.
The tool cards spell out inputs, outputs, limits, and best practices; the planner chooses the next action;
the verifier checks whether to continue, and the executor turns that action into a Python command and runs it.
The authors test on 16 benchmarks across text and vision, spanning math, science, medicine, agents, and visual reasoning.
They compare GPT-4o with zero-shot, CoT, and several agent frameworks using the same tools and budget.
OctoTools reaches 58.5 percent average accuracy, up 9.3 points over zero-shot GPT-4o and 7.7 over CoT.
With identical tools and budgets, it also beats AutoGen by 10.6 points, GPT-Functions by 7.5, and LangChain by 7.3.
That lift comes from coordination, not brute force.
The verifier often stops early, so the system averages only 2.56 executed steps,
and the toolset search is greedy, not exponential, so it can pick a better set efficiently.
On the hardest tool-heavy tasks, like Game of 24 and PathCLS, the gains are even larger.
And when tools fail, performance drops only a little; most errors come from weak tools or planning, not from the core framework.
So the big idea is simple: if a task needs several different kinds of reasoning,
give the model a planner, a verifier, and the right tools instead of asking one prompt to do everything itself.
